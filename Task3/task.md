Задание 3. Данные, масштабирование и отказоустойчивость

Что нужно сделать: спроектировать стратегию работы с данными в микросервисной архитектуре и обеспечить масштабируемость и отказоустойчивость хранилищ. Все решения должны быть обоснованы.
Конкретные задачи
1. Database per Service
Определите стратегию данных для каждого сервиса:
Сервис    Тип базы данных    Обоснование
Сервис ставок
Сервис кампаний
Сервис статистики
Сервис аналитики
Сервис финансов
2. Масштабирование баз данных
Опишите стратегию масштабирования, чтобы понять, для каких сервисов применить репликацию master-slave, какие данные и по какому ключу шардировать, нужны ли read replicas для сервиса аналитики и где применимо разделение ответственности команд и запросов (CQRS).
3. Кеширование
Спроектируйте стратегию кеширования. В частности, что кешировать (кампании, бюджеты, ставки), где разместить Redis, каковы TTL и стратегия инвалидации, а также как организовать прогрев кеша (cache warming).
4. Потоковая обработка данных
Опишите архитектуру потоковой обработки событий: топики Kafka, схему событий (Avro или JSON), группы потребителей и политику хранения.
5. Отказоустойчивость данных
Опишите отказоустойчивость данных: RPO и RTO для каждого сервиса, стратегию резервного копирования и соответствие принципам 12-факторных приложений.
В результате у вас должно получиться:
README.md — краткое описание.
database-strategy.md — выбор базы данных для каждого сервиса.
scaling.md — стратегии репликации и шардирования.
caching.md — дизайн кеширования.
event-streaming.md — архитектура Kafka.
diagrams/ — диаграммы данных.
